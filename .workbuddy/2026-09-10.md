## 第四轮（同日 18:17–18:45）：推送失败的真实原因是「凭证 + 无 tty」

用户再次要求「直接替换」仓库内容，于是做了两轮**真实推送尝试**，都失败：

| 尝试 | 命令 | 结果 |
|---|---|---|
| 1 | `GIT_TERMINAL_PROMPT=1 git push -u origin main` | 1m14s 后 `bash: line 1: /dev/tty: No such device or address` → `error: failed to execute prompt script` → `fatal: could not read Username` |
| 2 | `GCM_INTERACTIVE=true git -c credential.helper="C:/Users/Lenovo/AppData/Local/Programs/Git/mingw64/bin/git-credential-manager.exe" push` | 4m5s 后**完全相同**的 tty 报错（显式覆盖 helper 也没生效） |

**根因（可复用结论）**：
- 本机**没有任何 GitHub 凭证**：`cmdkey /list` 无 github 条目、无 `~/.git-credentials`、
  `~/.ssh` 只有 known_hosts（无密钥）。
- `git config --global credential.helper` 为空，实际生效的是**系统级 `helper-selector`**——
  它是一个**要读 `/dev/tty` 的 shell 脚本**。沙箱是非交互环境，没有 tty，脚本退出码 1，
  所以**登录窗口从未被唤起**。
- 判断链条要先分清：**网络问题 / 凭证缺失 / tty 不可用**。本轮前面一度误判为「网络封禁」，
  实际是后两者。第 2 次尝试能跑 4 分钟，也说明 TCP 连接本身是通的。

**这个沙箱无法完成任何交互式认证。** 可行的三条路：
1. 用户在自己真实终端跑 `git push -u origin main`（有 tty，GCM 正常弹窗）——最可靠
2. 用户提供 fine-grained PAT（只授权该仓库 Contents 读写）→ 用 `api.github.com` 走 REST API 完成
   （`api.github.com` 全程可达，不受 git 端口与 tty 影响）
3. 使用产品内置 GitHub 连接器（search_plugins 返回 id=`github`，描述含「克隆、推送代码」）
   → 渲染推荐卡片时返回 `Session config suggestion was cancelled because the session is no longer active`，未成功
